# Анализ качества диаризации и решение проблемы "прыгающих" спикеров

**Дата:** 21.01.2026
**Статус:** Implementation
**Проблема:** Нестабильные идентификаторы спикеров в длинных записях (сессия c6c2c640).

## Причина
Отсутствие stateful-механизма отслеживания неизвестных спикеров между чанками.
Текущий код (`rust/src-tauri/src/state/recording.rs`) полагается исключительно на глобальный `VoicePrintMatcher`. Если спикер не найден в глобальной базе (`speakers.json`), используется fallback на локальный `speaker_id` текущего чанка. Поскольку `local_id` (0, 1, 2) назначается независимо в каждом чанке (кто первый заговорил), один и тот же человек может быть "Собеседником 1" в одной минуте и "Собеседником 2" в другой.

## Решение: SessionSpeakerRegistry

Внедрение in-memory реестра для текущей сессии записи, который хранит эмбеддинги "неизвестных" спикеров, встреченных ранее в этой сессии.

### Алгоритм идентификации спикера (v2)

Для каждого сегмента с эмбеддингом `E`:

1. **Step 1: Global Search (существующий)**
   - `global_matcher.find(E)`
   - IF similarity > `THRESHOLD_HIGH` -> RETURN `global_name` (e.g. "Иван")

2. **Step 2: Session Search (новый)**
   - `session_registry.find(E)`
   - IF similarity > `THRESHOLD_MEDIUM` -> RETURN `session_name` (e.g. "Собеседник 2")

3. **Step 3: Register New (новый)**
   - `new_id = session_registry.count() + 1`
   - `name = "Собеседник {new_id}"`
   - `session_registry.add(name, E)`
   - RETURN `name`

### Архитектурные изменения

1.  **`aiwisper-ml`**: Добавление структуры `SessionSpeakerRegistry` в модуль `voiceprint`. Она будет хранить временные профили в памяти.
2.  **`state/recording.rs`**:
    - Инициализация `SessionSpeakerRegistry` при старте записи.
    - Передача реестра (через `Arc<RwLock<...>>`) в функцию транскрипции чанков.
    - Обновление логики присвоения имен в `transcribe_chunk_stereo`.

### Ожидаемый результат
- Стабильные метки спикеров на протяжении всей сессии.
- Корректное объединение реплик одного человека, разделенных длительными паузами.
- Отсутствие "прыгающих" имен при отсутствии голосового профиля в глобальной базе.
